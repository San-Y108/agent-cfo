## 1. Agent 聊天头像占比问题

### 1.1 现状（代码层）

文件：`components/console/agent-cfo-mascot.tsx` `AgentChatAvatar`（行 165–219）。

```tsx
// 容器
className="relative mt-0.5 h-[46px] w-[46px] shrink-0"
// 内层带 border-2（2px × 2 = 4px 边） + bg + 阴影
"border-2 bg-[#0a0f18]/80"
// 内嵌 img 容器
<div className="flex h-full w-full items-center justify-center p-1.5">
  <img
    className="h-full w-full select-none object-contain object-center scale-[0.88]"
  />
</div>
```

**`scale-[0.88]` + `p-1.5`（6px padding）+ `border-2` + `object-contain`** —— 这是问题四件套：
- `p-1.5` 把图片从 46px 压到 ~34px 可用区
- `scale-[0.88]` 再压 12% → ~30px
- `border-2` 占据 4px 又让中心 30px 的图偏向「像光盘里的一小块」
- `object-contain` 在正方形容器里渲染 1024×1024 透明背景 PNG 时，按非透明 bbox 居中显示 509×736（H 主导），但 509/736 = 0.69（瘦高形），在 46px 圆里**横向只占 ~30px，比例上像 CD 贴纸**

### 1.2 PNG 资产分析（headless 检测）

文件：`frontend/public/console/mascots/agent-cfo-avatar.png`

- 画布：1024 × 1024
- 实际非透明像素 bbox（alpha > 8）：**509 × 736**（占画布 35.7%）
- 长宽比：0.692（**竖高形**，人头 + 半身肩部构图）

**结论**：在 46px 圆里渲染 1024×1024 canvas 的 35.7% 内容，再被 `object-contain` 按外接圆裁切，**实际图像在视觉中只占 30%–40% 的圆面积**。这就是「像光盘贴纸」的根本原因。

### 1.3 修复目标

- 视觉上头像在圆内**占比 ≥ 80%**
- 保持 46px 圆容器（不要撑大，会挤压 Chat 气泡布局）
- 适配亮 / 暗双主题
- 保留 border + glow + 状态色（analyzing 态 cyan，idle 态 violet）

### 1.4 修复方案

**核心：内边距 / 缩放 / 容器尺寸三处一起调。**

#### 方案 A：调整 padding + scale（推荐先做）

```tsx
// 改前
<div className="flex h-full w-full items-center justify-center p-1.5">
  <img ... className="h-full w-full ... object-contain object-center scale-[0.88]" />
</div>
// 改后
<div className="flex h-full w-full items-center justify-center p-[2px]">
  <img ... className="h-full w-full ... object-contain object-center scale-[1.0]" />
</div>
```

| 改动 | 数值变化 | 实际像素（在 46px 圆里） |
|---|---|---|
| `p-1.5 → p-[2px]` | padding 12px → 4px | 可用区 46 → 42 px |
| `scale-[0.88] → scale-[1.0]` | 缩放 88% → 100% | 图占 42×42（再被 object-contain 限） |
| `object-contain` 按 0.69 长宽比 | 实际渲染 ≈ 29×42 | 占圆面积 ≈ 49% |

仍然不够。再加 **第二步**：

#### 方案 B：换 PNG（最有效，需用户确认）

把 `agent-cfo-avatar.png` 替换为 1:1 紧凑 bbox（占画布 > 80%）的图标版。
- 建议尺寸 512×512（更小）
- bbox 至少 410×410（占 80%）
- 主体居中，留 50px 安全区

执行方式：
- 用户/PM 切图（来源 `inbox/3d-assets/agent-cfo-mascot-source.png`，有 `scripts/remove-mascot-bg.py`）
- 或在 Plan 之外由 PM 用现成素材重新裁剪

#### 方案 C：CSS 缩放（不改 PNG，快速可逆）

如果用户暂时不换图，先用 CSS 把 PNG 拉大、裁掉透明外边：

```tsx
// 改 AgentChatAvatar 内部 img 容器
<div className="flex h-full w-full items-center justify-center overflow-hidden p-[2px]">
  <img
    src={src}
    alt="AgentCFO"
    className="pointer-events-none h-full w-full select-none object-cover object-[center_30%] scale-[1.45]"
    draggable={false}
  />
</div>
```

- `object-cover` 替代 `object-contain`：填满容器，裁掉多余
- `object-[center_30%]`：人脸偏上 30%，让头部作为视觉中心
- `scale-[1.45]`：在 cover 基础上再放大 45%，把原图的 35.7% 透明区从视觉上「挤出去」
- 改后实际头像在圆中**视觉占比 ≈ 80%**

**推荐执行顺序**：
1. **第一 PR**（最小风险）：方案 A + 方案 C 一起落地（同时去掉 `p-1.5`/`scale-[0.88]`，改 `object-cover` + `object-[center_30%]` + `scale-[1.45]`）。
2. **第二 PR**（如果用户对 PNG 仍不满意）：用方案 B 换 PNG。

### 1.5 Agent 详情卡（左侧 PersonaRail）同步检查

`agent-hub.tsx:350` 调用 `<AgentCfoMascot size="lg" interactive analyzing={analyzing} className="shrink-0" />`

`AgentCfoMascot`（同文件行 35–163）使用 `figureW × figureH = 252 × 232`（size=lg），`object-contain object-bottom` 渲染 `agent-cfo-mascot.png`。

主舞台尺寸够大，目前占比 80%+ 是 OK 的；但同样有 `object-contain object-bottom` —— 全身图被底部对齐，如果人脸在图的上半，会显得「脚在中间、头贴底部」。**建议改 `object-center` 让全身居中显示**。

### 1.6 验证

- Chrome dev tools 截图 `/console`，测量头像像素占圆面积比（用 DevTools 标尺 + 取色器）
- 亮 / 暗各一张，对照 eyeball
- typecheck + build 通过

**根因分两类**：
- **A. 直接写 Tailwind lime 调色板**（lime-400 / lime-700）—— 已有 navbar 给出正确双模式范式（`from-lime-700 dark:from-lime-400`），其他位置没照做。
- **B. 写 `#B5FF4D` 字面色**（policy.tsx:42 等）—— 完全绕开 token 体系。

### 2.2 修复方案

#### 2.2.1 通用规则

1. **HUD 强调色（绿/青/蓝/紫/玫红/琥珀）** → 走 `text-hud-X` / `bg-hud-X`，因为这些 token 已经双模式适配（light 用深色，dark 用霓虹）。
2. **品牌 lime 作「主题强调」（如启动动画、渐变文字、accent-fill 按钮）** → 必须用 **双 token 模式**：
   - **dark**:`from-lime-400 / to-lime-400 / text-lime-400`
   - **light**:`from-lime-700 / to-lime-700 / text-lime-700`
   - 范式参考：`navbar.tsx:142` 已有的 `from-lime-700 via-cyan-700 to-violet-700 dark:from-lime-400 ...`
3. **按钮变体里的「lime 主按钮」**（如 `HolographicButton variant="lime"` 当前实现）：
   - 现状：边框 `border-hud-lime/30` + 文字 `text-hud-lime`（`#4d7c0f`）+ 背景 `bg-white/[0.03]` —— **light 模式文字偏暗**
   - 修复：增加一个 **「accent-fill 变体」**，active/primary 态用 `bg-accent`（lime）+ `text-accent-fg`（黑），参考 `bg-accent text-accent-fg` 范式（`globals.css` 已定义 `--accent` 与 `--accent-fg`）
4. **`color: "#B5FF4D"` 字面色** → 一律改 token：
   - 想要"品牌 lime 持续发光"（dark 风格）→ `text-hud-lime`
   - 想要"主按钮填充 lime" → `bg-accent text-accent-fg`
5. **Generate Plan / Confirm Policy 类主按钮**（你说的「亮色模式变黑字」场景）：用 HolographicButton 新增的 `primary` 变体（`bg-accent text-accent-fg`），dark 模式保留现有 lime-tinted ghost，**只在 light 模式加 active 强底色**。

## 3. Wallets Vault Topology 节点星云图重构

### 3.1 现状（代码层）

文件：`components/console/wallet-hologram.tsx` `WalletTopology`（行 145–447）。

**当前构成**（行 174–185, 232–443）：
- 等角分布（`(360 / wallets.length) * i`，均匀一圈） + 固定半径 105（compact 72）
- 中心 CAW Core 圆 64×64
- 三圈同心脉冲圈（55/85/120px）
- SVG 中心 → 节点连线（淡蓝渐变）
- 沿连线动画数据包（cx/cy 0 → pos）
- 节点 button 44×44 圆
- mouse parallax（±1/25 视口偏移）
- 节点 label（钱包名 + 金额）位于节点下方

**为什么"潦草"**：
1. **几何感机械**：等角分布像"时钟刻度"，没有金库群组感
2. **节点尺寸太小**：44×44 圆 + 6px blur 阴影 + 8px label → 实际可读信息密度低
3. **视觉信息冗余**：中心 Core + 三圈脉冲 + 数据包 + 节点 button + hover sparkles + 节点 label + 鼠标视差 = 7 层叠加，单个 320×320px 容器里信息打架
4. **连接线太细**：1px 渐变线条在 hover 时 opacity 0.4 → 0.9，反差太弱
5. **compact 模式 = 3:1 横长比**：节点贴在 320×107 的窄长条里 → 更显局促

### 3.2 重构目标

> 关键词：**金库群组 + 资金流动** —— 突破「等角圆环」，做更有叙事感的拓扑。

设计目标：
- 让 3 个金库按**角色层级**（不是等角）布局：Agent Vault 居中、Multi-sig 围绕、Cold Storage 在远端
- 加入**资金大小可视化**（节点大小 / glow 强度 / 连线粗细与 valueUsd 成正比）
- 用**轨道弧线**替代直线，给"金库连通器"的视觉
- 减少冗余层（去掉三圈脉冲，保留 1 圈呼吸圈）
- 保留 hover/active 行为、compact 模式、亮暗双主题

### 3.3 重构方案（4 选 1 + 推荐 1）

#### 方案 X：Aurora Vault Map（推荐）

**灵感**：把 Topology 改成「极光金库地图」—— 中心是 CAW Core glow（缩小到 56×56），周围 3 个金库按**功能距离**分布：
- **Agent Vault**（最常交互）→ 距 Core 半径 80，尺寸 52×52
- **Multi-sig**（日常操作）→ 距 Core 半径 110，尺寸 48×48
- **Cold Storage**（大额、慢操作）→ 距 Core 半径 140，尺寸 56×56（最大但最远，体现「大但沉睡」）

**弧线连接**：用 SVG `<path d="M0,0 Q controlX controlY, targetX targetY">` 二阶贝塞尔，让 Agent Vault 走曲线上方、Multi-sig 走右弧、Cold Storage 走下弧 —— **三条不同弧度的 path，避免「等角对称」**。

**资金流量可视化**：
- 连线粗细 = valueUsd 比例（最大金库的线 strokeWidth 2.5，最小 0.8）
- 流动 packet 改用 SMIL/CSS animation，**沿 path 走**（不再是直线）—— 需要 `useDrawSvgLines` 升级支持 path
- 节点发光强度 = valueUsd 比例（最大金库 glow 强，最小弱）

**节点新设计**：
- 圆内：icon + 数字（valueUsd 缩写如 `$124k`）
- 圆外：标签（钱包名 + type chip）
- hover：放大到 1.12，sparkles 8 颗
- active：双层 ping + 持续 glow

**氛围层**：
- 中心 Core 周围 1 圈呼吸圈（删掉多余 2 圈）
- 背景：aurora 渐变（蓝→紫→青）缓慢旋转（用 conic-gradient + animate-spin-slow）

**compact 模式**：横排 3 个金库，连接线改为同高度弧形 hand-drawn 线

#### 方案 Y：Constellation Network

每个金库 = 一颗主星，中心 CAW Core = 中心恒星，节点之间画 3 条横/纵 90° 弧线（"星座"连线），鼠标 hover 时星与星之间发出流星。

**优点**：更新成本低（保留几何，添加流星）
**缺点**：本质还是「等角分布换皮」

#### 方案 Z：Treasury Heatmap 卡片

放弃星云图，改为**卡片流**：每个金库一张 BentoCard，标题 + 总值 + type + 状态点 + 链上活动数。
- 优点：信息密度极高，符合"控制台"调性
- 缺点：偏静态，丢失 "Topo 拓扑" 的视觉特色

#### 方案 W：Tilted 3D Isometric Vaults

用 CSS `transform: rotateX(35deg) rotateZ(-15deg)` 做一个 isometric 倾斜 3D，每个金库是「立体金库方块」放在网格上，CAW Core 是一台 ATM 机。鼠标移动时整片 3D 视差。

**优点**：极新颖
**缺点**：实现成本高 + 暗色模式表现好，亮色模式 isometric 阴影会很脏

### 3.4 推荐：方案 X（Aurora Vault Map）

**理由**：
- 保留 "Topo" 语义（不是替换为卡片流）
- 解决"等角机械感"——用弧线 + 不等距 + 比例化
- 信息密度高于原版（节点内显金额、连线粗细传递大小关系）
- 实现成本可控：复用现有 `useDrawSvgLines` + 扩展支持 `<path>` + 节点 layout 计算升级

### 3.5 实现要点（执行层落实）

#### 步骤 1：抽取 layout helper

新建 `lib/console/wallet-topology-layout.ts`：

```ts
export type LayoutStrategy = "aurora" | "constellation" | "isometric";

export interface LayoutNode {
  id: string;
  name: string;
  type: "Agent Vault" | "Multi-sig" | "Cold Storage";
  valueUsd: number;
  x: number; y: number;        // container-local 0-1 归一化坐标

  ringAngleDeg: number;         // 弧线方位
  ringPathD: string;            // SVG path d

}

export function layoutAurora(
  wallets: TopologyWallet[],
  compact: boolean
): { core: { x: number; y: number }; nodes: LayoutNode[] }
```
